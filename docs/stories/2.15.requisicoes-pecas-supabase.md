# Story 2.15: Requisições de Peças do Mecânico para Supabase Postgres (Nova Tabela)

**Epic:** Epic 2 (Persistência Real Supabase Postgres & RLS)
**Onda:** E — Ordem de Serviço Completa

**Dependências:** Story 2.14 (OS), Story 2.7 (Peças)

## Story

**Como** mecânico executando uma OS,
**Quero** que minhas requisições de peça ao estoque/secretaria sejam persistidas em Supabase Postgres,
**Para que** a secretaria e o administrador vejam o pedido em tempo real em qualquer dispositivo, e não apenas no `localStorage` do navegador em que o mecânico está logado.

---

## Acceptance Criteria

1. É criada a tabela `public.requisicoes_pecas` (nova), com FK para `ordens_servico(id)`, `pecas(id)` (quando a requisição referenciar uma peça já cadastrada no catálogo) e `funcionarios(id)` (mecânico solicitante), além de status da requisição (ex.: `pendente`, `atendida`, `recusada` — confirmar os valores reais usados hoje em `MecanicoPedirPecas.jsx`/`MecanicoContext.jsx` antes de fixar o `CHECK`).
2. `src/context/MecanicoContext.jsx` (hoje lê/grava `requisicoesPecas` diretamente em `localStorage` via `STORAGE_KEY_REQUISICOES_PECAS = 'dev_oficina_requisicoes_pecas'`, violando FR9 — acesso direto a `localStorage` fora de um repositório) é refatorado para delegar toda leitura/escrita de requisições a um novo `src/repositories/requisicoesPecasRepository.js`, expondo `carregarRequisicoesPecas()`, `criarRequisicaoPeca(dados)`, `atualizarStatusRequisicao(id, status)`.
3. `pedirPecaParaOS()` (função hoje exposta pelo `MecanicoContext`, consumida por `MecanicoPedirPecas.jsx`) mantém a mesma assinatura para os componentes de UI, mas internamente delega ao novo repositório.
4. RLS de `public.requisicoes_pecas` usa `public.papel_usuario()`: `mecanico` pode `INSERT`/`SELECT` (criar e ver suas próprias requisições, ou todas — decisão a confirmar com `@po`: se o mecânico só deve ver as próprias ou as de toda a equipe, dado que a fila de trabalho é compartilhada); `secretaria` e `admin` `SELECT`/`UPDATE` (atender/recusar a requisição).
5. Triggers de auditoria e `updated_at` anexadas à nova tabela.
6. Teste automatizado cobre: criação de requisição vinculada a uma OS, atualização de status, listagem, fallback local (preservando a chave `dev_oficina_requisicoes_pecas` para o modo offline).
7. Par mobile/portal do mecânico (`MecanicoPedirPecas.jsx` não tem par `mobile/` dedicado — é componente único consumido tanto no dashboard do mecânico quanto, potencialmente, em telas de secretaria que atendem a requisição; confirmar consumidores reais antes de considerar a verificação completa) verificado.
8. `npm run lint` e `npm test` sem novos erros; arquivos ≤ 400 linhas.

## Dev Notes

### Estado atual do código (violação real de FR9 a corrigir)
`src/context/MecanicoContext.jsx` grava `requisicoesPecas` diretamente em `localStorage` (`STORAGE_KEY_REQUISICOES_PECAS`), dentro do próprio Context Provider — sem passar por nenhum repositório em `src/repositories/`. Isso é uma violação preexistente de FR9 ("acesso a dados de cada domínio deve ocorrer através de interface de repositório explícita, sem acesso direto a `localStorage` a partir de componentes de UI") que esta story corrige junto com a migração para Supabase.

### O mesmo padrão se repete para outros três estados do `MecanicoContext`
`mecanicoAtivo` (`STORAGE_KEY_MECANICO_ATIVO`), `pecasDanificadas` (`STORAGE_KEY_PECAS_DANIFICADAS`) e `ferramentasDanificadas` (`STORAGE_KEY_FERRAMENTAS_DANIFICADAS`) têm o mesmo problema. `pecasDanificadas`/`ferramentasDanificadas` são tratados na Story 2.16 (próxima). `mecanicoAtivo` é sessão local do mecânico logado no dispositivo (identidade, não dado de domínio) — permanece em `localStorage` por ora, fora do escopo do Epic 2 (é resolvido pela autenticação real de funcionários, já implementada na Fase 0 de segurança via login Supabase Auth).

### Arquivos afetados
- **[NEW]** `supabase/migrations/{timestamp}_tabela_requisicoes_pecas.sql`
- **[NEW]** `src/repositories/requisicoesPecasRepository.js`
- **[MODIFY]** `src/context/MecanicoContext.jsx`
- **[NEW]** `tests/unit/requisicoesPecasRepository.test.js`

### Riscos
- `MecanicoContext.jsx` é um Context Provider React — migrar sua leitura de estado inicial de síncrona (`useState(() => localStorage.getItem(...))`) para assíncrona (chamada ao repositório) exige ajustar para um padrão `useEffect` + estado de carregamento, seguindo o contrato `{ dados, carregando, erro }` definido na Story 2.1 (AC4). Isso é uma mudança de padrão relevante dentro do Context — testar cuidadosamente para não introduzir um "flash" de lista vazia antes do carregamento assíncrono completar.
