## Story

**Como** equipe da oficina (admin e secretaria),
**Quero** que clientes e veículos tenham no Postgres o mesmo formato que o sistema usa hoje na tela, com código sequencial, IDs e regras de acesso definidos pelo banco, e repositórios assíncronos prontos para substituir o `localStorage`,
**Para que** a Story 2.6 troque todas as telas de uma vez para dados reais, sem perder campo nenhum do cadastro e sem "sucesso falso" (ADR-005).

---

## Acceptance Criteria

1. **Schema de clientes.** Migration `supabase/migrations/{timestamp}_clientes_veiculos_modelo_real.sql` adiciona a `public.clientes`: `codigo_cliente text UNIQUE NOT NULL DEFAULT lpad(nextval('public.seq_codigo_cliente')::text, 7, '0')` (sequência iniciando em 166, preservando o primeiro código atual `0000166`), `nome_fantasia text`, `rg_ie text`, `ativo boolean NOT NULL DEFAULT true`; define `id DEFAULT gen_random_uuid()::text`. `endereco` segue JSONB com as chaves `cep, logradouro, numero, complemento, bairro, cidade, uf`. Tudo com `IF NOT EXISTS`/idempotente.
2. **Schema de veículos.** A mesma migration adiciona a `public.veiculos`: `codigo_veiculo text UNIQUE NOT NULL DEFAULT 'VEIC-' || lpad(nextval('public.seq_codigo_veiculo')::text, 4, '0')`, `marca_codigo text`, `modelo_codigo text`, `ano_codigo text`, `chassi text`, `renavam text`, `ativo boolean NOT NULL DEFAULT true`; define `id DEFAULT gen_random_uuid()::text`. A FK `veiculos.cliente_id` passa de `ON DELETE CASCADE` para `ON DELETE RESTRICT` (excluir cliente com veículo passa a exigir decisão explícita; ver Riscos).
3. **Janela operacional (D4, ADR-005 §2.10).** É criada `public.em_horario_operacional()` (`STABLE`, `SET search_path = ''`, fuso `America/Sao_Paulo`, 08:00–18:59). As políticas de `INSERT`/`UPDATE` da secretaria em `veiculos` passam a exigir `em_horario_operacional()`; `clientes` **não** tem janela (D4); `admin` sem restrição. A política "Operadores atualizam OS em horario comercial" é recriada usando a função, com comportamento idêntico.
4. **RLS preservada.** `clientes`: admin total; secretaria `SELECT/INSERT/UPDATE`; mecânico `SELECT`; `DELETE` só admin. `veiculos`: igual, com a janela do AC3. Nenhuma política anônima; tudo via `public.papel_usuario()`.
5. **`clientesRepository.js` (reescrito)** exporta, todas assíncronas: `carregarClientes({ incluirVeiculos })`, `obterClientePorId(id)`, `buscarClientePorDocumento(documento)` (filtro no servidor por dígitos normalizados), `salvarCliente(cliente)` (insert/update por linha, com checagem de `updated_at` conforme ADR-005 §2.7 no update), `excluirCliente(id)`. O objeto devolvido mantém **o formato atual do front** (`codigoCliente`, `tipoPessoa`, `documento`, campos de endereço soltos, `value`/`id`/`label` como em `montarPayloadCliente`), e o objeto recebido é convertido para as colunas do AC1. `id` e `codigoCliente` de registro novo vêm do banco.
6. **`veiculosRepository.js` (novo)** exporta, todas assíncronas: `carregarVeiculos()` (com os campos do proprietário que hoje vêm de `carregarTodosVeiculosDaFrota`: `clienteId`, `clienteNome`, `clienteCodigo`, `clienteDocumento`, `clienteTelefone`, `clienteTipoPessoa`, `clienteCidade`, `clienteUf`), `obterVeiculoPorId`, `obterVeiculoPorPlaca`, `obterVeiculosDoCliente(clienteId)`, `salvarVeiculo(veiculo)` (inclui transferência de proprietário = `UPDATE` de `cliente_id`), `excluirVeiculo(id)`. Mantém o formato atual do front (`codigoVeiculo`, `marcaModelo`, `kmPadrao`, `value`/`id`/`label`).
7. **Erros com mensagem amigável** (`ErroRepositorio`, Story 2.1): documento duplicado → "CPF/CNPJ já cadastrado"; placa duplicada → "Placa já cadastrada"; exclusão de cliente com veículos (FK `RESTRICT`) → "Cliente possui veículos vinculados; transfira ou exclua os veículos antes"; escrita de veículo fora da janela pela secretaria → mensagem de horário.
8. **Modo local** (Supabase não configurado, dev/teste): os dois repositórios usam chaves próprias (`dev_oficina_clientes_v2`, `dev_oficina_veiculos_v2`) com o mesmo contrato, gerando `id`/códigos localmente só nesse modo. Sem fallback em falha no modo remoto.
9. **Testes.** Vitest (supabase-js mockado) cobre, para os dois repositórios: mapeamento ida e volta de todos os campos da tabela do Contexto, fail-closed, `id`/código vindos do banco, busca por documento normalizada, transferência de proprietário e as mensagens do AC7. Teste SQL transacional `supabase/tests/2.5_clientes_veiculos.test.sql` (com `ROLLBACK`) cobre `DEFAULT`s e sequências, `RESTRICT`, RLS por papel e a janela do AC3 (simulando horário). Migration aplicada via Supabase CLI e testes executados no banco, com evidência no Dev Agent Record.
10. `npm run lint` e `npm test` sem novos erros; nenhum arquivo novo/alterado > 400 linhas; **nenhuma tela alterada** nesta story.

## Dev Notes

- **Mapeadores isolados:** manter a conversão em funções puras (`clienteParaLinha`/`linhaParaCliente`, `veiculoParaLinha`/`linhaParaVeiculo`) num arquivo próprio (ex.: `src/repositories/mapeadores/clientesVeiculos.js`), testadas separadamente. `tipoPessoa` `F`/`J` ↔ `tipo` `PF`/`PJ`; `documento` ↔ `cpf_cnpj` (guardar só dígitos no banco; a máscara é da UI); `telefoneFixo` ↔ `telefone_secundario`; `kmPadrao` ↔ `km_atual` (inteiro); endereço solto ↔ `endereco` JSONB; `endereco` string formatada é derivada na leitura, não gravada.
- **Códigos pelo banco (ADR-005 §2.6):** `gerarProximoCodigoCliente`/`gerarProximoCodigoVeiculo` hoje leem o `localStorage` inteiro para achar o máximo. No modo remoto o código vem do `DEFAULT` da sequência (retornado por `.select().single()`); a UI que mostra "próximo código" antes de salvar passa a mostrar "gerado ao salvar" (troca de UI é da 2.6).
- **`ON DELETE RESTRICT`:** o `CASCADE` atual apagaria os veículos em silêncio ao excluir um cliente — comportamento que nem o `localStorage` tinha de forma explícita. Com 0 registros em produção, a mudança não tem custo de migração.
- **Veículos aninhados:** o contrato novo é de entidades separadas. `carregarClientes({ incluirVeiculos: true })` devolve `cliente.veiculos` montado a partir de `veiculos` (uma consulta com embed do PostgREST, `select('*, veiculos(*)')`), para facilitar a 2.6 nas telas que dependem do formato aninhado.
- **Negação por janela vs. por permissão:** o RLS nega as duas como `42501`, que `mapearErroPostgres` converte em `SEM_PERMISSAO`. Para cumprir a mensagem de horário do AC7, o repositório de veículos deve distinguir o caso (ex.: consultar `em_horario_operacional()` via RPC ao receber `42501` de uma secretaria e, se estiver fora da janela, lançar `FORA_DO_HORARIO`, que já existe em `CODIGOS_ERRO`).
- **Referências:** ADR-002 (contrato assíncrono), ADR-005 §2.1–§2.7, §2.10; ADR-008; Story 2.3 (padrão de teste SQL e harness PGlite: `scripts/sql-test-support/stub_supabase_auth.sql`).

### Riscos
- Divergência de nomenclatura entre front e banco é a maior fonte de bug: por isso os mapeadores são puros e testados ida e volta.
- `RESTRICT` muda o comportamento de exclusão; a mensagem do AC7 precisa chegar à tela na Story 2.6.
- A janela D4 em `veiculos` bloqueia a secretaria fora do horário; o admin não é afetado.
