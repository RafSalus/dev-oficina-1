# Story 1.9: Autenticação em Dois Fatores (MFA TOTP) no Portal de Gestão

**Status:** Ready for Review  
**Epic:** Epic 1 (Fundação de Produção e MVP 1)  
**Autor:** River (@sm)  
**Executor:** @dev  
**Quality Gate:** @architect  
**Dependências:** Story 1.1, Story 1.2  

---

## 1. Story Narrative

**Como** administrador ou proprietário da oficina Mecânica Gabriel,  
**Quero** configurar e validar segundo fator de autenticação (MFA TOTP via aplicativo autenticador) no portal de Gestão,  
**Para que** o acesso administrativo à oficina seja resistente a vazamento ou roubo de senha e permita meu acesso seguro 24/7 de qualquer lugar.

---

## 2. Acceptance Criteria (ACs)

- [x] **AC1:** As rotas `/gestao/mfa/configurar` e `/gestao/mfa/verificar` são criadas como páginas dedicadas e devidamente registradas em `src/App.jsx`.
- [x] **AC2:** A página de configuração (`GestaoMfaConfigurarPage.jsx`) invoca `enrollMfa()` gerando e exibindo o QR Code (SVG nativo) e o segredo em texto claro com botão de cópia para entrada manual.
- [x] **AC3:** A validação do código de 6 dígitos realiza o desafio (`challenge`) e confirmação (`verify`), promovendo a sessão no `AdminAuthContext` para o nível `aal2`.
- [x] **AC4:** Usuários com fator cadastrado que fizerem login com email/senha em `/gestao/entrar` são automaticamente redirecionados para `/gestao/mfa/verificar`, onde digitam o token de 6 dígitos antes de acessar o dashboard.
- [x] **AC5:** A interface das telas de MFA respeita integralmente as 16 regras do `SYSTEM_RULES.md`: layout limpo e sóbrio em Preto, Branco e Azul oficial (`#0284c7`), sem scroll vertical na tela principal (R2), sem verde (R7) e com inputs de 16px mínimo em mobile (R10).
- [x] **AC6:** O administrador autenticado pode gerenciar fatores cadastrados e invocar desativação com confirmação (`unenrollMfa`).
- [x] **AC7 (Procedimento de Emergência):** O `README.md` documenta a rotina de recuperação/remoção de emergência do fator via SQL no Supabase em caso de perda ou quebra do smartphone do administrador.

---

## 3. Integration Verification (IVs)

- [x] **IV1:** Fluxo completo de ativação com Google Authenticator ou similar, garantindo elevação para AAL2 e redirecionamento para o dashboard.
- [x] **IV2:** Tentativa de acessar `/gestao/dashboard` com sessão pendente de MFA redireciona com sucesso para `/gestao/mfa/verificar`.
- [x] **IV3:** Logout e novo login exige a inserção do token TOTP de 6 dígitos.

---

## 4. SYSTEM_RULES.md Checklist

- [x] **R1 / R2 / R3:** Tela com `overflow-hidden`, limite até o footer, sem scroll na janela principal.
- [x] **R4 / R7:** Branco, Preto e Azul oficial da marca (`#0284c7`). Sem verde.
- [x] **R8 / R16:** Notificações top-right via `sonner`; confirmações in-modal sobre o formulário.
- [x] **R10:** Inputs numéricos com `font-size: 16px` no mobile para impedir zoom automático no celular.
