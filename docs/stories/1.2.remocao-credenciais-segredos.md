# Story 1.2: Remoção de Credenciais do Código e Rotação de Chaves

**Status:** Ready for Review  
**Epic:** Epic 1 (Fundação de Produção e MVP 1)  
**Autor:** River (@sm)  
**Executor:** @dev  
**Quality Gate:** @architect  

---

## 1. Story Narrative

**Como** responsável técnico pela segurança do sistema,  
**Quero** que nenhuma credencial ou chave secreta exista hardcoded em arquivos versionados no repositório,  
**Para que** a chave do Supabase possa ser rotacionada sem alterar código-fonte e o projeto em nuvem não sofra acessos não autorizados.

---

## 2. Acceptance Criteria (ACs)

- [x] **AC1:** `src/lib/supabase.js` lê a URL e chave anônima exclusivamente de `import.meta.env.VITE_SUPABASE_URL` e `import.meta.env.VITE_SUPABASE_ANON_KEY`, com todos os valores literais de fallback eliminados.
- [x] **AC2:** `.env.example` contém apenas variáveis obrigatórias com valores de placeholder limpos (`https://seu-projeto.supabase.co`, `sua-chave-anon-supabase-aqui`), sem credenciais reais. Variáveis de infraestrutura AIOX são segregadas.
- [x] **AC3:** `.gitignore` garante que arquivos `.env`, `.env.local`, `.env.*.local` nunca sejam versionados ou commitados.
- [x] **AC4:** Varredura em todo o código-fonte confirma zero ocorrências de credenciais hardcoded (`git grep -i "sb_publishable"` retorna 0 resultados em arquivos versionados).
- [x] **AC5:** Na ausência de variáveis de ambiente configuradas, o sistema mantém o estado `unconfigured`, permitindo a inicialização da aplicação em modo offline/desenvolvimento com aviso explícito no console em ambiente DEV.
- [x] **AC6 (Setup do Usuário Admin Inicial):** O `README.md` documenta o procedimento claro para provisionar o primeiro usuário com papel `admin` no Supabase (Authentication ➔ Users com `user_metadata: { role: "admin" }` ou via SQL).

---

## 3. Integration Verification (IVs)

- [x] **IV1:** Autenticação administrativa no Supabase lê variáveis exclusivamente do arquivo `.env` local.
- [x] **IV2:** Com variáveis ausentes ou não configuradas, a aplicação inicializa sem quebrar em modo offline/desenvolvimento.
- [x] **IV3:** Varredura no código (`git grep -i "sb_publishable"` e `git grep -i "lqjwzlgwcfhxpefnfnzt"`) retorna zero ocorrências em todo o repositório.
